# algpy

NumPy number types for Cayley-Dickson, Clifford, and multicomplex algebras, with up to 32 real components.
Use them as scalars or NumPy array dtypes for arithmetic, elementary functions, and algebra-specific operations.

## Installation

Requires Python 3.10 or later and NumPy. Install from this checkout:

```sh
python -m pip install .
```

## Quick start

```python
import numpy as np
from algpy.algebras import quaternion

q = quaternion(1, 2, 3, 4)  # coefficients of 1, i, j, k
r = quaternion(2)         # omitted coefficients are zero

q * r
np.exp(q)
q.inv()

values = np.array([q, r], dtype=quaternion)
np.sin(values)
quaternion.to_float(values)  # shape (2, 4)
```

## Algebras

General constructors live in `algpy.algebras.general`. Supply one to five
real parameters to `cayleydickson`, `clifford`, or `multicomplex` to create a type
with 2, 4, 8, 16, or 32 components.
The parameters are the squares of the successive generators.

The numbered constructors `cayleydickson1`–`cayleydickson5`,
`clifford1`–`clifford5`, and `multicomplex1`–`multicomplex5` are also
available. The suffix counts generators; the dimension is two to that power.
A general type's `K` is mutable: changing it changes operations on existing
scalars and arrays of that type. Create separate types for parameter sets
you want to use simultaneously.

The tables below cover dimensions 2, 4, and 8 for each family. Read a cell as
**row times column**. The labels
`1, e₀, e₁, e₀₁, e₂, e₀₂, e₁₂, e₀₁₂` denote the coefficient basis,
in the same order as `Type.basis()` and `Type.to_float()`. Subscripts identify
the generators in each product.

The generators are `e₀`, `e₁`, and `e₂`, with squares `k₀`, `k₁`, and `k₂`.
The remaining basis elements are `e₀₁ = e₀e₁`, `e₀₂ = e₀e₂`, `e₁₂ = e₁e₂`, and
`e₀₁₂ = (e₀e₁)e₂`. Products such as `k₀k₁e₀₁` mean multiplication by real
parameters. Substitute your type's `K`; for example, all `kᵢ = -1` gives
octonions in the Cayley-Dickson table.

For dimension 2, take the upper-left 2×2 block and only `k₀`. For dimension
4, take the upper-left 4×4 block and `k₀, k₁`. The full tables use
`K = (k₀, k₁, k₂)` in dimension 8.

### Cayley-Dickson

The Cayley-Dickson construction successively doubles real algebras.
Cayley-Dickson algebras are generally noncommutative from dimension 4 and
nonassociative from dimension 8.

| ×    | 1    | e₀    | e₁     | e₀₁    | e₂    | e₀₂     | e₁₂    | e₀₁₂    |
| ---- | ---- | ----- | ------ | ------ | ----- | ------- | ------ | ------- |
| 1    | 1    | e₀    | e₁     | e₀₁    | e₂    | e₀₂     | e₁₂    | e₀₁₂    |
| e₀   | e₀   | k₀    | e₀₁    | k₀e₁   | e₀₂   | k₀e₂    | −e₀₁₂  | −k₀e₁₂  |
| e₁   | e₁   | −e₀₁  | k₁     | −k₁e₀  | e₁₂   | e₀₁₂    | k₁e₂   | k₁e₀₂   |
| e₀₁  | e₀₁  | −k₀e₁ | k₁e₀   | −k₀k₁  | e₀₁₂  | k₀e₁₂   | −k₁e₀₂ | −k₀k₁e₂ |
| e₂   | e₂   | −e₀₂  | −e₁₂   | −e₀₁₂  | k₂    | −k₂e₀   | −k₂e₁  | −k₂e₀₁  |
| e₀₂  | e₀₂  | −k₀e₂ | −e₀₁₂  | −k₀e₁₂ | k₂e₀  | −k₀k₂   | k₂e₀₁  | k₀k₂e₁  |
| e₁₂  | e₁₂  | e₀₁₂  | −k₁e₂  | k₁e₀₂  | k₂e₁  | −k₂e₀₁  | −k₁k₂  | −k₁k₂e₀ |
| e₀₁₂ | e₀₁₂ | k₀e₁₂ | −k₁e₀₂ | k₀k₁e₂ | k₂e₀₁ | −k₀k₂e₁ | k₁k₂e₀ | k₀k₁k₂  |

Construct Cayley-Dickson algebras and elements as follows:

```python
from algpy.algebras.general import cayleydickson

CD = cayleydickson(-1, -1)  # quaternion algebra, dimension 4

print(CD.N, CD.K) # Dimension 4, [-1.0, -1.0]

x = CD(1, .2, .3, .4)
```

The following fixed specializations are exported from `algpy.algebras`
and `algpy.algebras.cayleydickson`:

| Types             | Real components | Corresponding general algebra       |
| ----------------- | --------------- | ----------------------------------- |
| `real`            | 1               | Real numbers                        |
| `quaternion`      | 4               | `cayleydickson(-1, -1)`             |
| `octonion`        | 8               | `cayleydickson(-1, -1, -1)`         |
| `sedenion`        | 16              | `cayleydickson(-1, -1, -1, -1)`     |
| `trigintaduonion` | 32              | `cayleydickson(-1, -1, -1, -1, -1)` |

Sedenions and trigintaduonions are nonassociative and have zero divisors.

### Clifford

The Clifford algebra with parameters `k0, ..., k(n-1)` is generated by elements
`e_i` with `e_i² = k_i` and `e_i e_j = -e_j e_i` for distinct generators.
Products of distinct generators form a `2ⁿ`-element basis.
Clifford algebras are associative. Distinct generators anticommute, so
multiplication is noncommutative from dimension 4.

| ×    | 1    | e₀    | e₁     | e₀₁     | e₂    | e₀₂    | e₁₂     | e₀₁₂    |
| ---- | ---- | ----- | ------ | ------- | ----- | ------ | ------- | ------- |
| 1    | 1    | e₀    | e₁     | e₀₁     | e₂    | e₀₂    | e₁₂     | e₀₁₂    |
| e₀   | e₀   | k₀    | e₀₁    | k₀e₁    | e₀₂   | k₀e₂   | e₀₁₂    | k₀e₁₂   |
| e₁   | e₁   | −e₀₁  | k₁     | −k₁e₀   | e₁₂   | −e₀₁₂  | k₁e₂    | −k₁e₀₂  |
| e₀₁  | e₀₁  | −k₀e₁ | k₁e₀   | −k₀k₁   | e₀₁₂  | −k₀e₁₂ | k₁e₀₂   | −k₀k₁e₂ |
| e₂   | e₂   | −e₀₂  | −e₁₂   | e₀₁₂    | k₂    | −k₂e₀  | −k₂e₁   | k₂e₀₁   |
| e₀₂  | e₀₂  | −k₀e₂ | −e₀₁₂  | k₀e₁₂   | k₂e₀  | −k₀k₂  | −k₂e₀₁  | k₀k₂e₁  |
| e₁₂  | e₁₂  | e₀₁₂  | −k₁e₂  | −k₁e₀₂  | k₂e₁  | k₂e₀₁  | −k₁k₂   | −k₁k₂e₀ |
| e₀₁₂ | e₀₁₂ | k₀e₁₂ | −k₁e₀₂ | −k₀k₁e₂ | k₂e₀₁ | k₀k₂e₁ | −k₁k₂e₀ | −k₀k₁k₂ |

Construct Clifford algebras and elements as follows:

```python
from algpy.algebras.general import clifford

Cl = clifford(-1, 1, 0)  # dimension 8, including a zero-square generator

print(Cl.N, Cl.K) # Dimension 8, [-1.0, 1.0, 0.0]

z = Cl(1, .2, .3, .4)
```

The following fixed geometric algebras are exported from `algpy.algebras`
and `algpy.algebras.clifford`:

| Type   | Geometry dimension | Generators | Real components | Corresponding general algebra |
| ------ | ------------------ | ---------- | --------------- | ----------------------------- |
| `pga1` | 1                  | 2          | 4               | `clifford(0, 1)`              |
| `pga2` | 2                  | 3          | 8               | `clifford(0, 1, 1)`           |
| `pga3` | 3                  | 4          | 16              | `clifford(0, 1, 1, 1)`        |
| `pga4` | 4                  | 5          | 32              | `clifford(0, 1, 1, 1, 1)`     |
| `cga1` | 1                  | 3          | 8               | `clifford(-1, 1, 1)`          |
| `cga2` | 2                  | 4          | 16              | `clifford(-1, 1, 1, 1)`       |
| `cga3` | 3                  | 5          | 32              | `clifford(-1, 1, 1, 1, 1)`    |

Here the suffix counts **geometry dimensions**. `Type.N` still gives the
number of real coefficients. Projective geometric algebra (PGA) puts the
null generator first, followed by the Euclidean generators. Conformal
geometric algebra (CGA) puts the negative and positive generators first,
followed by the Euclidean generators. These fixed types have no mutable `K`.
`cga3` is the fixed specialization of the five-generator conformal metric.

```python
from algpy.algebras import pga2, cga3

n, x, y = pga2.gens()
assert n*n == pga2.zero()

em, ep, ex, ey, ez = cga3.gens()
origin = (em - ep)/2
infinity = em + ep
point = origin + 2*ex + 3*ey + 4*ez + (2**2 + 3**2 + 4**2)/2*infinity
assert point*point == cga3.zero()
```

The PGA and CGA types also implement the [lattice API](#lattices): join `|`
(the exterior product), meet `&` (the regressive product), `bottom()`,
`top()`, and the Poincaré duals `ldual()`/`rdual()`, plus `~` and `dual()`
for `pga2`, `pga4`, `cga1`, and `cga3`, which have an odd number of
generators. These operations do not depend on the metric, so they agree with
`exterior2`–`exterior5` on the same coefficients; `*` stays the geometric
product.

In the dual PGA model, with points as left duals of homogeneous vectors, `&`
spans flats through points and `|` intersects them:

```python
from algpy.algebras import pga2

n, x, y = pga2.gens()
p, q = (n + x).ldual(), (n + y).ldual()  # the points (1, 0) and (0, 1)
line = p & q
assert line | p == 0 and line | q == 0
```

In CGA's outer-product representation, `|` spans round objects through
points and `&` intersects them:

```python
import numpy as np
from algpy.algebras import cga2

em, ep, ex, ey = cga2.gens()
origin, infinity = (em - ep)/2, em + ep

def point(x, y):
    return origin + x*ex + y*ey + (x*x + y*y)/2*infinity

circle = point(1, 0) | point(0, 1) | point(-1, 0)  # unit circle
axis = point(0, 0) | point(1, 0) | infinity        # the line y = 0
pair = circle & axis                               # the point pair (±1, 0)
assert circle | point(0, -1) == 0
assert np.allclose(cga2.to_float(pair | point(1, 0)), 0)
```

### Multicomplex

The multicomplex algebra with parameters `k0, ..., k(n-1)` is generated over
the reals by commuting elements `e_i` satisfying `e_i² = k_i`. Its basis
consists of products of distinct generators, giving `2ⁿ` real components.
Multicomplex algebras are associative and commutative.

| ×    | 1    | e₀    | e₁    | e₀₁    | e₂    | e₀₂    | e₁₂    | e₀₁₂   |
| ---- | ---- | ----- | ----- | ------ | ----- | ------ | ------ | ------ |
| 1    | 1    | e₀    | e₁    | e₀₁    | e₂    | e₀₂    | e₁₂    | e₀₁₂   |
| e₀   | e₀   | k₀    | e₀₁   | k₀e₁   | e₀₂   | k₀e₂   | e₀₁₂   | k₀e₁₂  |
| e₁   | e₁   | e₀₁   | k₁    | k₁e₀   | e₁₂   | e₀₁₂   | k₁e₂   | k₁e₀₂  |
| e₀₁  | e₀₁  | k₀e₁  | k₁e₀  | k₀k₁   | e₀₁₂  | k₀e₁₂  | k₁e₀₂  | k₀k₁e₂ |
| e₂   | e₂   | e₀₂   | e₁₂   | e₀₁₂   | k₂    | k₂e₀   | k₂e₁   | k₂e₀₁  |
| e₀₂  | e₀₂  | k₀e₂  | e₀₁₂  | k₀e₁₂  | k₂e₀  | k₀k₂   | k₂e₀₁  | k₀k₂e₁ |
| e₁₂  | e₁₂  | e₀₁₂  | k₁e₂  | k₁e₀₂  | k₂e₁  | k₂e₀₁  | k₁k₂   | k₁k₂e₀ |
| e₀₁₂ | e₀₁₂ | k₀e₁₂ | k₁e₀₂ | k₀k₁e₂ | k₂e₀₁ | k₀k₂e₁ | k₁k₂e₀ | k₀k₁k₂ |

Construct Multicomplex algebras and elements as follows:

```python
from algpy.algebras.general import multicomplex

MC = multicomplex(-1, 1)  # dimension 4, commuting generators

print(MC.N, MC.K) # Dimension 4, [-1.0, 1.0]

z = MC(1, .2, .3, .4)
```

The following fixed specializations are exported from `algpy.algebras`
and `algpy.algebras.multicomplex`:

| Types                           | Real components | Corresponding general algebra            |
| ------------------------------- | --------------- | ---------------------------------------- |
| `complex1`–`complex5`           | 2, 4, 8, 16, 32 | `multicomplex` with every parameter `-1` |
| `dual1`–`dual5`                 | 2, 4, 8, 16, 32 | `multicomplex` with every parameter `0`  |
| `splitcomplex1`–`splitcomplex5` | 2, 4, 8, 16, 32 | `multicomplex` with every parameter `1`  |

`algpy.algebras.complex` is an alias for `complex1`; both refer to the same
algebra type. These are distinct from Python's built-in `complex` type.

```python
from algpy.algebras import dual5

e0, e1, e2, e3, e4 = dual5.gens()
x = .3 + e0 + e1 + e2 + e3 + e4
np.exp(x)[31]  # exp(.3): the fifth mixed derivative
```

### Jets

The jet algebra `jetN` is the truncated polynomial ring `R[e]/(e^(N+1))`
for `N = 1, ..., 5`: a single nilpotent generator `e` with `e^(N+1) = 0`,
and `N + 1` coefficients, those of `1, e, ..., e^N`. Jets are associative
and commutative. Applying a function to `x + e` gives its Taylor
coefficients, the **normalized derivatives** `f^(k)(x)/k!` for
`k = 0, ..., N`, so arithmetic and elementary functions of jets perform
forward-mode automatic differentiation of any order up to `N`.

| Types         | Real components | Generator               |
| ------------- | --------------- | ----------------------- |
| `jet1`–`jet5` | 2, 3, 4, 5, 6   | `e`, with `e^(N+1) = 0` |

These differ from `dual1`–`dual5`, the tensor products of `N` dual numbers:
`dualN` has `N` generators and `2^N` components, and its top coefficient
holds the unnormalized mixed derivative `f^(N)(x)`. A jet needs only
`N + 1` components for the same order. `jet1` and `dual1` are the same
algebra. Constructor keywords are `x` for the real part and `x1`, ..., `xN`
for the coefficients of `e`, ..., `e^N`.

```python
import math
from algpy.algebras import jet5

e, = jet5.gens()
f = np.exp(np.sin(.3 + e))       # composition, as in forward AD
f[3]                             # (d/dx)^3 exp(sin(x)) at .3, divided by 3!
jet5.to_float(np.exp(.3 + e))    # exp(.3)/k! for k = 0..5
```

The conjugate is the automorphism `e -> -e`. The generic minimal polynomial
is `(t - x)^(N+1)`, so `eivals()` repeats the real part `N + 1` times, and
`norm()` is its absolute value. `a.grade[k]` is the coefficient of `e^k`.

The complex jets `complex_jet1`–`complex_jet5` are `C[e]/(e^(N+1))`, with
`N + 1` complex coefficients stored as `2(N + 1)` real components: the
coefficient of `e^k` is `a[2k] + i*a[2k+1]`. Their generators are `i` and
`e`, at positions 1 and 2. Holomorphic functions of `z + e` give the
normalized complex derivatives `f^(k)(z)/k!` on the principal branches.
The conjugate is complex conjugation `i -> -i`; `norm()` is the modulus of
the leading coefficient, and `a.grade[k]` is the complex coefficient of
`e^k`. Constructor keywords are `x, y` for the leading coefficient and
`x1, y1, ..., xN, yN` for the others.

```python
from algpy.algebras import complex_jet3

i, e = complex_jet3.gens()
f = np.log(1 + .5*i + e)               # log(z) at z = 1 + .5i
complex_jet3.to_float(f)[[4, 5]]       # -1/(2 z^2): real and imaginary parts
```

## Lattices

`algpy.lattices` (and `algpy.lattices.clifford`) export the exterior algebras
`exterior1`–`exterior5`, with 2, 4, 8, 16, and 32 components. They are the
Clifford algebras with every generator square zero, in the same coefficient
order as `clifford(0, ..., 0)`, but they expose a lattice API instead of an
algebra API:

| Operation                 | Scalar interface         | NumPy interface                                | Identity                       |
| ------------------------- | ------------------------ | ---------------------------------------------- | ------------------------------ |
| Join (exterior product)   | `a \| b`                 | `np.bitwise_or`                                | `Type.bottom()`, the scalar 1  |
| Meet (regressive product) | `a & b`                  | `np.bitwise_and`                               | `Type.top()`, the pseudoscalar |
| Left and right duals      | `a.ldual()`, `a.rdual()` | `algpy.lattices.ldual`, `algpy.lattices.rdual` |                                |
| Dual, odd dimensions only | `~a`, `a.dual()`         | `np.invert`                                    |                                |

The duals are Poincaré dualities that exchange join and meet. On basis blades,
`a | a.ldual() == top` and `a.rdual() | a == top`; they are mutually inverse,
and `a & b == (a.ldual() | b.ldual()).rdual()`. In odd dimensions `ldual`
and `rdual` coincide, so `exterior1`, `exterior3`, and `exterior5` also provide
`~a` and `a.dual()`. In even dimensions they differ in sign on odd grades,
and `~a` raises `TypeError`.

`algpy.lattices.ldual` and `algpy.lattices.rdual` are NumPy ufuncs that accept
values of every exterior, PGA, and CGA type, with broadcasting, strided inputs and `out=`:

```python
from algpy.lattices import exterior2, ldual, rdual

values = exterior2.from_float(np.arange(8.).reshape(2, 4))
assert (rdual(ldual(values)) == values).all()
```

```python
from algpy.lattices import exterior3

e0, e1, e2 = exterior3.gens()
line = e0 | e1                     # span of e0 and e1
plane = e1 | e2
assert line & plane == e1          # their intersection
assert e0 | e1 | e2 == exterior3.top()
assert ~e0 == e0.ldual() == e0.rdual() == e1 | e2
```

Lattice types are also vector spaces: `+`, `-`, unary signs, multiplication
and division by real numbers, `np.add`, `np.subtract`, `np.multiply` and
`np.divide` with real operands, and equality. Products of two lattice values
are only available as join and meet. Real numbers embed as multiples of
`bottom()`, so `a | 2 == 2*a`. The PGA and CGA types implement the same
lattice operations alongside their algebra API. The array conversions `Type.to_float`,
`Type.from_float`, `Type.N`, `Type.basis()`, and `Type.gens()` behave as for
algebras. Scalars also provide `Type.zero()`, the grade projections
`a.grade[k]`, and `a.norm2()` for the sum of squared coefficients.

## Arrays and coefficients

Each algebra type has `N` real coefficients, in the order returned by
`Type.basis()`. Scalars accept those coefficients as positional arguments;
omitted coefficients are zero. Scalars also support indexing, so `q[0]` is
the real coefficient.

`Type.gens()` returns only the generators as a one-dimensional array of the
algebra's dtype. A `2ⁿ`-dimensional algebra has `n` generators, in parameter
order, at basis positions `1, 2, 4, 8, 16` as applicable. The identity is excluded;
`real.gens()` returns an empty array.

Use `Type.from_float(data)` to turn an array with final axis of length `N`
into an algebra array. `Type.to_float(values, dtype=None)` restores that
coefficient axis; its default output dtype is `float64`.

```python
coefficients = np.array([[1., 2., 3., 4.], [2., 0., 0., 0.]])
values = quaternion.from_float(coefficients)  # shape (2,), dtype quaternion
restored = quaternion.to_float(values)       # shape (2, 4), dtype float64
np.testing.assert_array_equal(restored, coefficients)

single = quaternion.from_float([1, 2, 3, 4])  # zero-dimensional array
scalar = single.item()                       # quaternion scalar
quaternion.to_float(scalar)                  # shape (4,)
quaternion.to_float(values, dtype=np.float32)
```

For a numeric multiplication table at any supported dimension, use
`Type.coeffs()`. Entry `[i, j]` is `Type.basis()[i] * Type.basis()[j]`:

```python
A = clifford(-1, -1, -1)
basis = A.basis()
e0, e1, e2 = A.gens()
assert e0 == basis[1] and e1 == basis[2] and e2 == basis[4]
assert basis[1] * basis[2] == basis[3]
assert basis[2] * basis[1] == -basis[3]
products = A.coeffs()
A.to_float(products)  # shape (8, 8, 8): row, column, output coefficient
```

Inputs to `from_float` are converted to `float64`. Conversions can share
memory with contiguous `float64` data; use `.copy()` when you need independent
storage. Strided inputs are accepted, with copying as needed.

The supported NumPy ufuncs work elementwise on scalars and arrays, including
broadcasting, real numeric operands, strided inputs, and `out=`:

```python
values = np.array([q, r], dtype=quaternion)
scaled = values[:, None] * np.array([1., 2., 3.])  # shape (2, 3)
out = np.empty_like(values)
assert np.exp(values, out=out) is out
np.add(values, 1, out=out)
```

For a scalar, `q.re()`, `q.im()`, `q.real`, and `q.imag` return algebra-valued
projections, and `q.to_re()` returns the real coefficient as a Python float.
`q.is_real()` checks whether all non-real coefficients are zero.
For algebra arrays, `.real`/`.imag` and `np.real`/`np.imag` do not extract the
algebra's components. Use `Type.to_float(array)[..., 0]` for real
coefficients and `Type.to_float(array)[..., 1:]` for the remaining components.

## Operations and elementary functions

All algebras expose the following operations. NumPy functions in the last
column operate on both scalars and arrays; named methods operate on scalars.

| Operation                       | Scalar interface                               | NumPy interface                                                 |
| ------------------------------- | ---------------------------------------------- | --------------------------------------------------------------- |
| Arithmetic                      | `+`, `-`, `*`, `/`, `**`                       | `np.add`, `np.subtract`, `np.multiply`, `np.divide`, `np.power` |
| Unary signs                     | `+a`, `-a`                                     | `np.positive`, `np.negative`                                    |
| Equality                        | `==`, `!=`                                     | `np.equal`, `np.not_equal`                                      |
| Inverse, square, conjugate      | `a.inv()`, `a.square()`, `a.conjugate()`       | `np.reciprocal`, `np.square`, `np.conjugate`                    |
| Grade projection                | `a.grade[k]`                                   |                                                                 |
| Exponential and logarithm       | `a.exp()`, `a.expm1()`, `a.log()`, `a.log1p()` | `np.exp`, `np.expm1`, `np.log`, `np.log1p`                      |
| Square root                     | `a.sqrt()`                                     | `np.sqrt`                                                       |
| Trigonometric functions         | `a.sin()`, `a.cos()`, `a.tan()`                | `np.sin`, `np.cos`, `np.tan`                                    |
| Inverse trigonometric functions | `a.asin()`, `a.acos()`, `a.atan()`             | `np.arcsin`, `np.arccos`, `np.arctan`                           |
| Hyperbolic functions            | `a.sinh()`, `a.cosh()`, `a.tanh()`             | `np.sinh`, `np.cosh`, `np.tanh`                                 |
| Inverse hyperbolic functions    | `a.asinh()`, `a.acosh()`, `a.atanh()`          | `np.arcsinh`, `np.arccosh`, `np.arctanh`                        |

`a.grade[k]` keeps the coefficients whose basis index has `k` generator
bits; `len(a.grade)` is the number of generators plus one, and iterating over
`a.grade` yields every grade. In a Clifford algebra these are the usual grade
projections. The view is read-only, since algebra values are immutable.

The scalar inverse-function methods also accept the NumPy spellings, such
as `a.arcsin()` and `a.arccosh()`. Class methods `Type.zero()`, `Type.one()`,
and `Type.from_re(x)` construct the additive identity, multiplicative
identity, and an embedded real number.

Functions follow real domains or the principal complex branches available
in the chosen algebra. Out-of-domain values can produce NaN components.
For example, split-complex functions must be defined at every real channel,
and dual logarithms and general powers require a positive real coefficient.
Dual reciprocals require a nonzero real coefficient. Nilpotent components
require the function to be differentiable to the corresponding order.

### Powers and interpolation

Multiplication order matters in noncommutative algebras:

| Scalar call                | Definition                                            |
| -------------------------- | ----------------------------------------------------- |
| `a.ipow(n)`                | Integer power, including singular and nilpotent bases |
| `a.lpow(b)`                | `exp(b * log(a))`                                     |
| `a.rpow(b)`                | `exp(log(a) * b)`                                     |
| `a ** b`, `np.power(a, b)` | Right-power, as in `a.rpow(b)`                        |
| `a.mix(b, t)`              | `a * ((a.inv() * b) ** t)`, with those parentheses    |

`lpow` and `rpow` accept an exponent from the same algebra or a real number.
They agree in commutative algebras. `ipow` accepts integer objects, including
NumPy integer scalars, within the signed 64-bit range; it raises
`OverflowError` outside that range. Negative integer powers require an
invertible base, and exponent zero returns the identity.

```python
from algpy.algebras import dual1

epsilon = dual1(0, 1)
assert epsilon.ipow(2) == dual1.zero()
assert epsilon.ipow(0) == dual1.one()
```

### Norms, polynomials, and eigenvalues

`a.norm()` returns an algebraic norm. Its Python return type depends on the
algebra type:

| Algebras                                                                                                                                                                     | Return type        |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `real`, `complex1`–`complex5`, `dual1`–`dual5`, `jet1`–`jet5`, `complex_jet1`–`complex_jet5`, `quaternion`, `octonion`, `sedenion`, `trigintaduonion`, `pga2`–`pga4`, `cga3` | Built-in `float`   |
| `splitcomplex1`–`splitcomplex5`, `pga1`, `cga1`, `cga2`, and all general parameterized types                                                                                 | Built-in `complex` |

Complex-valued norms always return `complex`, even for a purely real result;
changing `K` does not change that return type. For the Euclidean length of
the coefficient vector, use `np.linalg.norm(Type.to_float(a))`.

`a.minpoly()` returns the coefficients of the algebra's **generic minimal
polynomial**, evaluated at `a`, in ascending order (constant term first).
This polynomial can have repeated roots and can have higher degree than the
minimal polynomial of the particular element. `a.eivals()` returns its roots
as a NumPy complex array, including multiplicities.
For `cga3` and `clifford5` types, the generic polynomial has degree eight:
`minpoly()` returns nine real coefficients and `eivals()` returns eight eigenvalues.

The Clifford types with an odd number of generators also provide the
minimal polynomial over their centre `span{1, w}`, where `w` is the
pseudoscalar. The centre is a two-dimensional algebra, available as
`Type.center`. `a.center_minpoly()` returns the ascending coefficients as an
array of that type, each `c` standing for `c[0] + c[1]*w`. Multiplied by its
conjugate under `w -> -w`, this polynomial gives `a.minpoly()`.

| Types          | `w*w`            | `Type.center`                | Coefficients           |
| -------------- | ---------------- | ---------------------------- | ---------------------- |
| `clifford1`    | `k0`             | the type itself              | 2: `[-a, 1]`           |
| `clifford3`    | `-k0*k1*k2`      | `clifford1` with `K = [w*w]` | 3: a central quadratic |
| `clifford5`    | `k0*k1*k2*k3*k4` | `clifford1` with `K = [w*w]` | 5: a central quartic   |
| `pga2`, `cga1` | `0`, `1`         | `dual1`, `splitcomplex1`     | 3                      |
| `pga4`, `cga3` | `0`, `-1`        | `dual1`, `complex1`          | 5                      |

```python
from algpy.algebras.general import clifford

Cl = clifford(-1, -1, -1)
x = Cl(1, 2, 3, 4, 5, 6, 7, 8)
p = x.center_minpoly()     # dtype Cl.center, with Cl.center.K == [1.0]
w = Cl.basis()[-1]
total = sum(((c[0] + c[1]*w)*x.ipow(i) for i, c in enumerate(p)), Cl.zero())
assert np.allclose(Cl.to_float(total), 0)
```

For `clifford3` and `clifford5`, `Type.center` is created once per type, and
its `K` follows changes to the type's `K`.

### Multiplication matrices

`a.lmat()` and `a.rmat()` return independent, writable `(N, N)` NumPy
`float64` arrays in coefficient order. Left matrices act on columns, and
right matrices on rows:

```python
np.testing.assert_allclose(q.lmat() @ quaternion.to_float(r),
                           quaternion.to_float(q * r))
np.testing.assert_allclose(quaternion.to_float(q) @ r.rmat(),
                           quaternion.to_float(q * r))
```

These describe a single multiplication in every algebra. In nonassociative
algebras, keep parentheses explicit; products and elementary functions of
multiplication matrices need not represent the corresponding algebra operations.
